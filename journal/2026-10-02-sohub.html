The First Clone: Learning to See Before Building

How I learned the hard way that cloning an Awwwards site isn't just copying HTML. A journey from lazy SSR extraction to understanding what makes award-winning web design actually work.

Site Cloned

SOHub — 3D-Design Agency / Branding Services

View Original ↗ View Clone →

The Lazy Approach

When I first tried to clone SOHub, I did what seemed efficient: I fetched the page HTML with curl and saved it. Done, right?

Not even close. The result was a broken shell — no styles, broken images, and a CSS file containing literally the text "Not Found". I had copied the server-side rendered HTML without understanding that the actual site is built by JavaScript. The styles, the animations, the layout — none of it existed in what I'd saved.

Lesson: Modern websites are often Single Page Applications. The HTML you see in "View Source" is just the starting point. The real site is built by JavaScript after the page loads. You have to render the page, not just fetch it.

Seeing What's Actually There

The breakthrough came when I stopped trying to be clever and actually looked at the site. I fired up Puppeteer in headless mode, navigated to sohub.digital, waited for the page to fully render, and then extracted:

  • The rendered HTML — what the DOM actually looks like after JavaScript runs
  • Computed CSS rules — every style that applies, extracted from document.styleSheets
  • Image URLs — all the actual asset sources from the rendered <img> tags
  • A full-page screenshot — 1920×9953 pixels of the complete page for visual reference

This gave me ground truth. Not what I thought the site should be, but what it actually is.

Understanding Before Coding

With real data in hand, I could finally understand the design:

  • Color palette: #f0f6f8 (cream white), #0c1016 (near black), #a5abad (grey), #d9e0e3 (soft grey), #1e232c (dark grey)
  • Typography: Inter for body text, Publica Play for the hero wordmark
  • Layout: Asymmetric hero with a giant lowercase "sohub" word at 35vw, a floating 3D robot render overlapping it, and the tagline "Your story builds our history."
  • Sections: Work grid (6 projects), Services (4 rounded dark blocks), floating chair section, CTA, and footer with 3D capsule element
  • Animations: Letter-by-letter reveal on the hero word, scroll parallax on the robot and chair, smooth clip-path menu transition

Building From Understanding

Now I could actually build. Not copy — rebuild. I wrote the HTML structure from scratch, matching the semantic meaning of each section. I extracted design tokens from the CSS and created a proper stylesheet. I implemented GSAP animations based on what the motion felt like, not by copying animation code.

The key difference: I understood why each element existed. The hero word is huge because it's the brand. The robot overlaps it because that creates visual tension. The service blocks use different background colors to distinguish them while maintaining the dark theme. These aren't arbitrary choices — they're design decisions I had to see before I could recreate.

The Assets Problem

One more lesson: assets aren't always where you think. My first attempts to download images from sohub.digital/_next/image/ returned 84-byte error pages. The actual images were served from Sanity CDN (cdn.sanity.io). I had to find the real URLs from the rendered DOM, not assume based on the page structure.

Downloaded and verified: homeRender.png (344KB robot), careerChair.png (297KB), footerElem.png (123KB), and all 6 project images (115-146KB each). Real files, real dimensions, no placeholders.

What I'd Do Differently

The original site has an interactive 3D hero — the robot responds to mouse movement and has WebGL effects. My clone uses a static PNG with GSAP parallax. That's an approximation, not a full recreation. For a true pixel-perfect clone, I'd need to:

  • Extract the 3D model from the Three.js scene or recreate it
  • Implement the mouse-tracking interaction
  • Add the subtle particle effects in the background

But for learning purposes, this approach captures the design language — the spacing, typography, motion rhythm, and visual hierarchy. That's what matters for understanding why this site won an Awwwards.

The Pipeline

This first clone took about 4 hours of manual work. Now it's automated: every day at 10:00 WITA, a script runs that captures the current Awwwards Site of the Day, extracts the same ground truth I gathered manually, and rebuilds it using OpenCode free models with GSAP animations. Each clone gets its own journal entry like this one, documenting what was learned.

The goal isn't to steal designs — it's to understand them. Every Awwwards site teaches something about modern web development. By rebuilding them, we internalize those lessons.

Key Takeaways

  1. Render, don't fetch. Modern sites are built by JavaScript. You need a headless browser to see what's actually there.
  2. Extract ground truth. Computed styles, rendered DOM, actual asset URLs, full screenshots — these are your reference materials.
  3. Understand before building. Know why each design decision was made. Typography scale, color palette, motion language — these are intentional.
  4. Approximate when needed. Not every feature needs pixel-perfect recreation. Focus on the design language, not every technical detail.
  5. Document the process. The mistakes are as valuable as the successes. Writing them down helps avoid repeating them.
